# Лабораторная работа № 2. Java Reflection — генератор объектов

## Цель

Познакомиться с Java Reflection API и научиться использовать информацию о типах во время выполнения программы. Спроектировать генератор случайных значений и объектов, работающий не только с заранее известными классами.

## Задание

Реализуйте генератор, которому можно передать `Class<?>` требуемого типа и получить значение этого типа. Примеры запросов:

```java
Integer number = generateValueOfType(Integer.class);
String text = generateValueOfType(String.class);
Rectangle rectangle = generateValueOfType(Rectangle.class);
Shape shape = generateValueOfType(Shape.class);
int[] numbers = generateValueOfType(int[].class);
List<?> items = generateValueOfType(List.class);
Map<?, ?> entries = generateValueOfType(Map.class);
```

Это примеры использования, а не обязательная сигнатура метода. Вы можете выбрать собственный API, но должна сохраняться возможность запросить значение по `Class<?>`.

Используйте `java.lang.reflect` для исследования пользовательских типов и создания их экземпляров. Для генерации случайных значений примитивных типов и строк используйте `java.util.Random`.

Классы в пакете `classes` задают ориентир по сложности объектов. **Нельзя подменять универсальную генерацию набором специальных веток, рассчитанных исключительно на имена классов из шаблона.** Генератор должен работать и с новыми классами сопоставимой сложности.

## Обязательные возможности

### Поддерживаемые типы

| Категория | Примеры |
| --- | --- |
| Примитивные типы и их обёртки | `int`, `double`, `boolean`, `char`, `Integer`, `Double` и др.  |
| Строки | `String` |
| Перечисления | `enum Color { RED, GREEN, BLUE }` |
| Массивы | `int[]`, `String[]`, `Color[]`, `Rectangle[]` |
| Списки | `List` (хотя бы один поддерживаемый вариант списка) |
| Отображения | `Map` (хотя бы один поддерживаемый вариант отображения) |
| Пользовательские классы | `Rectangle`, `Triangle` и новые классы аналогичной сложности |
| Интерфейсы и абстрактные классы | `Shape` и другие типы с подходящими реализациями |

Для массивов обязательна поддержка как минимум одномерных массивов с элементами поддерживаемых типов. Для `List` и `Map` достаточно продемонстрировать генерацию **хотя бы одного непустого варианта** каждого вида, содержащего сгенерированные элементы и пары ключ–значение соответственно. Поддержка всех разновидностей коллекций и произвольных сочетаний generic-типов **не требуется**. Выбранные ограничения опишите в своём решении.

Размеры массивов и коллекций, диапазоны и распределения случайных значений, длины строк и прочие параметры генерации определяются студентом. Генерация не должна сводиться к постоянному возвращению одной заглушки. Генерация `void`/`Void` не требуется.

### Пользовательские объекты

Генератор должен создавать объекты пользовательских классов с применением Reflection API. Способ создания и заполнения объектов, а также выбор конструкторов остаются на усмотрение студента.

Помимо классов из шаблона, решение должно поддерживать новые подходящие классы без добавления отдельных проверок на их имена, а также классы из пакета `classes`, включая возможность запросить генерацию по `Shape.class`. В результате такого запроса должен получиться объект, совместимый с `Shape`. Аналогичное требование относится к поддерживаемым абстрактным классам.

### Аннотация `@Generatable`

Разработайте собственную аннотацию `@Generatable` и используйте её в работе генератора. Аннотация должна иметь **реальное значение для логики программы**, а не присутствовать только формально.

Правила её применения и интерпретации студент выбирает самостоятельно. В README своего решения необходимо объяснить выбранную семантику, в том числе для интерфейсов, абстрактных классов и их реализаций.

### Ошибки генерации

Если запрос невозможно обработать, генератор должен завершаться **осмысленным исключением**, по которому можно понять причину неудачи. Возврат `null` как универсальный признак ошибки не допускается.

## Реализация (описание решения)

### API

Основной класс — `org.example.generator.Generator`.

```java
Generator generator = new Generator();      // случайный seed
Generator seeded = new Generator(42L);      // одинаковый seed — одинаковые значения

Integer number = generator.generateValueOfType(Integer.class);
String text = generator.generateValueOfType(String.class);
Rectangle rectangle = generator.generateValueOfType(Rectangle.class);
Shape shape = generator.generateValueOfType(Shape.class);
int[] numbers = generator.generateValueOfType(int[].class);
List<?> items = generator.generateValueOfType(List.class);
Map<?, ?> entries = generator.generateValueOfType(Map.class);

generator.register(SomeImplementation.class); // ручная регистрация реализации
```

### Поддерживаемые типы

| Категория | Что поддерживается |
| --- | --- |
| примитивы и обёртки | все 8 примитивов и их обёртки |
| строки | `String`, `CharSequence` |
| перечисления | любой `enum`, возвращается случайная константа |
| массивы | любые одномерные и многомерные массивы поддерживаемых типов |
| списки | `List`, `Collection`, `Iterable`, `ArrayList` — создаётся `ArrayList` |
| отображения | `Map`, `HashMap`, `LinkedHashMap` — создаётся `LinkedHashMap` |
| пользовательские классы | любые новые классы: конструктор и заполнение полей |
| интерфейсы и абстрактные классы | через классы, помеченные `@Generatable` |
| `record` | через канонический конструктор |

Размеры и диапазоны заданы константами: целые `[-1000, 1000]`, дробные `[-1000, 1000]`
с двумя знаками, строки длиной `4–12`, массивы и коллекции размером `1–5`.

### Ограничения

Выбранные ограничения реализации:

- поддерживаются только списки (`ArrayList`) и отображения (`LinkedHashMap`);
  `Set`, `Queue`, `TreeMap` и другие коллекции отклоняются с понятной ошибкой;
- элементы «сырого» `List` генерируются как `Object` (числа, строки, `boolean`, символы);
  ключи «сырой» `Map` — строки, иначе уникальные ключи почти недостижимы;
- JDK-классы без отдельного правила (`Thread`, `LocalDate`) не поддерживаются;
- `void` и `Void` не генерируются — у них нет значений;
- глубина вложенности ограничена `5`; на границе ссылочные значения равны `null`,
  что защищает от бесконечной рекурсии для классов вроде `BinaryTreeNode`;
- `final`-поля не перезаписываются: их значения задаёт конструктор (важно для `record`);
- поле неподдерживаемого типа не ломает объект — остаётся значением по умолчанию;
- сканируются только каталоги classpath, jar-файлы — нет (для них есть `register(...)`);
- генератор не потокобезопасен: один экземпляр — один поток.

### Аннотация `@Generatable`

Аннотация ставится на **конкретный класс** и означает: «этот класс можно использовать
как реализацию для его интерфейсов и абстрактных классов».

Пример: `Rectangle` и `Triangle` помечены `@Generatable` и реализуют `Shape`,
поэтому `generateValueOfType(Shape.class)` возвращает один из них. Класс `Square`
тоже реализует `Shape`, но не помечен — в каталог он не попадает, и `Shape.class`
его никогда не вернёт (при этом `Square.class` можно запросить напрямую).

Правила применения:

1. На интерфейсы и абстрактные классы аннотацию ставить не нужно: их экземпляры
   не создаются напрямую. Точкой входа для них служат помеченные конкретные классы-реализации.
2. При первом создании генератора на classpath ищутся конкретные классы с аннотацией —
   это каталог реализаций. Каталог кешируется, повторно classpath не сканируется.
3. Запрос интерфейса или абстрактного класса: из каталога берутся совместимые классы,
   порядок перемешивается, создаётся первый успешный кандидат.
4. Если подходящих классов нет — выбрасывается `GenerationException` с подсказкой
   про `@Generatable` и `register(...)`.
5. Прямой запрос конкретного класса (`Rectangle.class`, `Product.class`,
   `BinaryTreeNode.class`) работает и без аннотации — класс известен явно.
6. Классы из jar-файлов сканированием не находятся, их нужно добавлять через
   `generator.register(SomeImpl.class)`.

### Создание пользовательских объектов

1. Выбирается конструктор с наименьшим числом параметров (публичные — раньше);
   если он не подошёл, пробуется следующий. Приватные конструкторы открываются
   через `setAccessible(true)`.
2. Аргументы конструктора генерируются по их generic-типам: `Cart(List<Product>)`
   получает список именно товаров.
3. После создания заполняются все нестатические и нефинальные поля, включая
   унаследованные от не-JDK предков.
4. Если объект реализует `SelfValidating`, вызывается `isValid()`; невалидный
   объект отбрасывается и создаётся заново (не более 1000 попыток).

### Ошибки

Ошибки генерации сообщаются исключением `GenerationException` с понятным текстом;
`null` для корректного типа не возвращается. Примеры сообщений:

```text
Тип void не может быть сгенерирован
Класс java.lang.Thread не поддерживается генератором
Нет реализации для org.example.testmodel.Courier: пометьте класс аннотацией @Generatable
  или зарегистрируйте его через register(...)
Не удалось создать org.example.testmodel.BrokenConstructor:
  BrokenConstructor() -> java.lang.IllegalStateException: boom
```

### Предметные ограничения (дополнительное задание)

`SelfValidating` — интерфейс с методом `isValid()`. Генератор проверяет объект
после создания и заполнения полей:

- `Rectangle` — обе стороны положительные;
- `Triangle` — стороны положительные и выполняется неравенство треугольника;
- `Square` — сторона положительная;
- `NeverValid` (тестовый класс) — всегда `false`, поэтому генератор честно сообщает,
  что за 1000 попыток валидный объект не получился.

### Тесты

`./gradlew test` запускает 52 теста в 9 классах. Проверяются свойства результата,
а не конкретные случайные значения.

| Класс | Что проверяет |
| --- | --- |
| `ScalarGenerationTest` | примитивы, обёртки, диапазоны, строки, символы, перечисления |
| `ArrayGenerationTest` | массивы примитивов, строк, enum, объектов, многомерные |
| `CollectionGenerationTest` | непустые `List` и `Map`, generic-поля |
| `ObjectGenerationTest` | классы шаблона, новые классы, `record`, приватный конструктор, глубина |
| `AbstractTypeGenerationTest` | `Shape.class`, абстрактный класс, ошибка без реализации |
| `GeneratableSemanticsTest` | каталог реализаций, непомеченные классы, `register` |
| `FailureHandlingTest` | `null`, `void`, JDK-типы, падающий конструктор, невозможное ограничение |
| `DomainConstraintTest` | валидные прямоугольники, треугольники и фигуры |
| `DeterminismAndDepthTest` | одинаковый seed, ограничение глубины, отсутствие переполнения стека |
